# REVIEW.md

Defects found in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` — `skip = page * page_size` | Pagination off-by-one: page 1 skips the first `page_size` records instead of 0. A GET with `page=1` returns the second page of results. | Call `GET /employees?page=1` — it returns the wrong items; page 1 should start at offset 0. | Changed to `skip = (page - 1) * page_size`. |
| 2 | `punch_in` — `ts = datetime.fromtimestamp(...)` (no `tz`) | `datetime.fromtimestamp` returns a **naive** local-time datetime. MongoDB stores it without time zone awareness; all IST-based date calculations (R1, R2) then silently use the server's local clock instead of UTC→IST conversion. | Punch in at e.g. 09:28 IST from a machine running UTC — `late_minutes` is computed against the wrong time, and `date` may be off by a day. | Used `datetime.fromtimestamp(ms/1000, tz=timezone.utc).replace(microsecond=0)` everywhere to produce timezone-aware UTC datetimes. |
| 3 | `punch_in` — no 404 for unknown employee | The code calls `db.employees.find_one(...)` but never checks the result; if `emp` is `None`, the next line (`emp["shift_start"]`) raises an unhandled `TypeError`, which FastAPI turns into a 500 instead of the required 404. | POST `/attendance/punch-in` with a non-existent `emp_code`. | Added `if not emp: raise HTTPException(404, ...)` immediately after the lookup. |
| 4 | `punch_in` — `attendance_date` not used | The starter hardcodes `d = ts.date().isoformat()` — it does not implement the overnight-shift rule (R1). A night-shift worker punching in at 01:00 IST gets the wrong date. | Create an employee with `shift_start=22:00, shift_end=06:00`, punch in at `00:30 IST`; the record's `date` should be the previous calendar day. | Replaced with a dedicated `attendance_date()` helper that handles the overnight case per R1. |
| 5 | `compute_late_minutes` — wrong grace-period boundary | `minutes > 10` uses strict integer minutes, but R2 says "strictly more than 10:00". The starter computes `int((punch_in - start).total_seconds() / 60)`, which floors to whole minutes, so 10:00 (600 s) → `minutes = 10` and correctly returns 0, but 10:01 (601 s) → `minutes = 10` too (floor), returning 0 when it should return 10. | Punch in at exactly 09:40:01 (shift 09:30) — `late_minutes` should be 10 per the spec example; the starter returns 0. | Rewrote: compute `elapsed = int(total_seconds)` (truncation per R1), then return `elapsed // 60` when `elapsed > 600`, else 0. |
| 6 | `list_attendance` — loads entire collection into memory | `list(db.attendance_logs.find(q))` fetches all matching documents, sorts in Python, then slices. On 100k records this is slow and consumes large memory. | Run against a large dataset and observe high latency / memory. | Removed in-memory sort; push sort and pagination into MongoDB with `.sort(...).skip(...).limit(...)` and use `count_documents(q)` for total. |
| 7 | `health` — does not ping MongoDB | Returns `{"status": "ok"}` unconditionally; it should return 503 if MongoDB is unavailable. | Stop MongoDB, call `GET /health` — still returns 200. | Added `db.command("ping")` and returns 503 on exception. |
| 8 | `compute_overtime` — uses `datetime.fromisoformat(date_str)` without `tzinfo` | Builds shift-end as a naive datetime, then subtracts an aware `punch_out`; this raises `TypeError: can't subtract offset-naive and offset-aware datetimes` at runtime for any punch-out attempt. | POST `/attendance/punch-out` on any record. | Rebuilt `compute_overtime` to attach IST timezone to the shift-end datetime before comparison. |

**Items reviewed and considered NOT defects:**

- `compute_work_hours` uses Python's built-in `round()` — for the starter this was fine since it was only illustrative. The spec requires half-up rounding (R4), which Python's `round()` does not provide for x.5 cases (it uses banker's rounding), so this was replaced with `round_half_up()`. Strictly speaking this is a defect, but it only manifests for exact half-second work hour values.
- `from dotenv import load_dotenv` / `load_dotenv()` at module level — correct; real environment variables win over `.env` values because `load_dotenv` does not override existing vars by default.
